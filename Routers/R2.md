# R2 – Router Configuration

## 1. Device Overview

| Parameter | Value |
|---|---|
| Hostname | R2 |
| IOS Version | 15.9 |
| Router ID | 2.2.2.2 |
| OSPF Process | 1 |
| OSPF Area | 0 |
| Role | Transit Router, Default Route Propagation |

R2 acts as the transit router between the internal OSPF network and the OPNsense firewall. It maintains a static default route toward the firewall and advertises it to the other OSPF routers.

## 3. Configuration Summary

| Feature | Implementation |
|---|---|
| Dynamic Routing | OSPF Area 0 |
| Router ID | 2.2.2.2 |
| OSPF Authentication | MD5 on R1 transit link |
| Default Route | Static route toward OPNsense |
| Default Route Propagation | OSPF `default-information originate` |
| Firewall Connection | 10.10.250.2/30 |
| Syslog | Fedora – 10.10.20.50 |
| Time Synchronization | NTP server 1.1.1.1 |
| Remote Management | SSH v2 |

## 4. Routing and Firewall Integration

R2 uses a static default route pointing to the OPNsense firewall:

- R2 GigabitEthernet0/1: `10.10.250.2/30`
- OPNsense LAN: `10.10.250.1/30`
- Default gateway: `10.10.250.1`

The command `default-information originate` allows R2 to advertise the default route through OSPF to the internal network.

Only GigabitEthernet0/0 is configured as a non-passive OSPF interface. The firewall-facing interface is not part of the OSPF process.

## 5. Notes

- R2 participates in OSPF Area 0 through GigabitEthernet0/0.
- Loopback0 is used as the OSPF router ID reference and Syslog source interface.
- OSPF MD5 authentication is configured on the R1 transit link.
- The default route points to OPNsense.
- R2 synchronizes its clock with R1 using authenticated NTP.
- GigabitEthernet0/2 and GigabitEthernet0/3 are administratively disabled.
